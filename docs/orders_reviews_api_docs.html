POST
Create Order
/orders/
▶
🔑 Auth Required Client only

Creates a new order for a company service. The order starts in pending status.

Request Body
{
  "service": 7,        // required — CompanyService ID
  "notes": "Urgent"  // optional — free text
}
Response 201
{
  "service": 7,
  "notes": "Urgent"
}
201 Order created
400 Validation error — check errors object
Next step: After creating an order, upload required documents via POST /orders/{id}/documents. Documents can only be uploaded while status is pending.
POST
Upload Document
/orders/{id}/documents
▶
🔑 Auth Required Client only

Uploads a document file for a specific requirement on this order. Only one document per requirement is allowed. OCR processing starts automatically in the background.

URL Parameters
ParamTypeDescription
idintegerOrder primary key
Request — multipart/form-data
FieldTypeDescription
requirementintegerRequirement ID (must belong to this order's procedure)
filefileThe document file
// JS fetch example
const form = new FormData();
form.append('requirement', 3);
form.append('file', fileInput.files[0]);

fetch('/api/v1/orders/42/documents', {
  method: 'POST',
  headers: { 'Authorization': `Bearer ${token}` },
  body: form,
});
Response 201
{
  "requirement": 3,
  "file": "https://storage.govconnect.ai/orders/documents/abc.pdf"
}
201 Document uploaded and OCR queued
400 Order not pending, duplicate requirement, or wrong requirement for this procedure
404 Order not found
Constraint: Document upload is blocked when order status is not pending. Show the upload UI only while status === "pending".
POST
Pay Order
/orders/{id}/pay
▶
🔑 Auth Required Client only

Marks an accepted order as paid. This transitions the order from accepted → paid. No request body needed.

Response 200
{
  "message": "Payment completed successfully.",
  "status": "paid"
}
200 Payment recorded, status is now paid
400 Order not in accepted state, or already paid
404 Order not found

PATCH
Update Order Status
/orders/{pk}/status/
▶
🔑 Auth Required Company owner only

Transitions an order to a new status. Only valid transitions are accepted — see the status flow below. Automatically sends a notification to the client on status change.

Request Body
{
  "status": "accepted"  // see allowed transitions below
}
Allowed Transitions
FromTo
pendingaccepted, rejected
paidin_progress
in_progresscompleted
accepted, completed, rejected— (terminal)
Response 200
{ "status": "accepted" }
200 Status updated
400 Invalid transition — cannot change status from X to Y
404 Order not found
⭐
Reviews
All review endpoints are scoped to an order: /orders/{id}/review. A review can only be created or modified once the order status is completed. Each order can have at most one review.
GET
Get Order Review
/orders/{id}/review
▶
🌐 Public

Returns the review for a specific order. No authentication needed.

Response 200
{
  "comment": "Excellent service, very professional.",
  "rating": 5
}
200 Review returned
400 Order has no review yet
404 Order not found
POST
Submit Review
/orders/{id}/review
▶
🔑 Auth Required Client only

Creates a review for a completed order. Each order can only be reviewed once.

Request Body
{
  "rating": 5,                                  // required — integer 1–5
  "comment": "Excellent service, very professional."  // optional, max 200 chars
}
Response 200
{
  "comment": "Excellent service, very professional.",
  "rating": 5
}
200 Review created
400 Order not completed, or already reviewed
PATCH
Edit Review
/orders/{id}/review
▶
🔑 Auth Required Client only

Partially updates an existing review. Send only the fields you want to change.

Request Body (partial)
{
  "comment": "Updated comment."  // or "rating", or both
}
200 Review updated
400 No review exists for this order
DELETE
Delete Review
/orders/{id}/review
▶
🔑 Auth Required Client only

Permanently deletes the review for this order. Returns 204 No Content on success.

204 Review deleted
400 No review exists for this order
404 Order not found
GET
All Reviews for a Company
/company/{id}/reviews
▶
🌐 Public

Returns every review submitted for all orders belonging to a specific company. Use this on company profile pages to show the overall rating feed.

URL Parameters
ParamTypeDescription

Response 200
[

  { "comment": "Good communication.", "rating": 5 }

200 Reviews array (may be empty)
404 No company matches this id

Order Status Flow

Full lifecycle — teal = company action, purple = client action

pending
→ company
accepted
→ client pays
paid
→ company
in_progress
→ company
completed
pending
→ company rejects
rejected

After completed, the client can submit a review via /orders/{id}/review.

Authentication

All protected endpoints require a JWT Bearer token in the Authorization header.

// Include in every authenticated request
Authorization: Bearer <access_token>
